CH 01
Introduction to CentOS Linux
Overview of Linux vs UNIX, the file system tree, partitions, and how to keep your system updated.
Key Concepts
  • CentOS is community-supported, RHEL-aligned
  • Linux = Kernel + Tools (utils, GUI, packages)
  • UNIX file system = tree starting at root /
  • Full path always begins with /
  • CentOS is open source (GPL)
Partitions
  • /boot — startup partition
  • swap — virtual memory
  • / — root: stores system & user data
Update Command
dnf update -y
Key Terms
CentOSCommunity Enterprise OS — community-supported, RHEL-aligned
RHELRed Hat Enterprise Linux
KernelCore that manages hardware and resources
Root /Top of the file system tree
PartitionDisk section for a specific purpose (e.g., /boot, swap)
File SystemFormat for storing files (e.g., ext4, xfs)
Quick Review
CentOS ↔ RHEL Linux = UNIX-based + GPL Tree starts at / /boot · swap · / dnf update -y

Users & Permissions
Manage user accounts, passwords, groups, and account security on CentOS.
Add / View Users
  • useradd username
    create user
  • passwd username
    assign password
  • cat /etc/passwd
    all user info
  • cut -d: -f1 /etc/passwd
    list usernames only (-f1 = first column)
Delete User ⚠
  • userdel -r username
    delete user + home dir
  • userdel username
    delete user only
  • rm -f /home/username
    manually remove home dir
Password Options
  • useradd username
  • passwd -d username
    create user WITHOUT password
  • chage -d 0 username
    force password change at next login
Lock / Unlock User
  • passwd -l username
    🔒 lock user
  • passwd -u username
    🔓 unlock user
Rename User
  • usermod -l ra makara2
    rename makara2 → ra (home dir keeps old name)
  • usermod -d /home/ra -m ra
    also rename home dir
Common issue: user process running
ps -u bora -o pid,cmd
kill 4363

CH 06
Compressions and Crontab
Compress files with zip and tar, then automate backups with crontab.
Zip & Unzip

Compresses files/directories while keeping the originals. Saves in MS-DOS format.

Install
  • dnf install zip unzip
Usage
  • zip -r backup.zip folder1 folder2
    compress
  • unzip backup.zip
    extract
Tar (Tape Archive)

Stores data in UNIX format (preserves uid, gid, permissions) — unlike zip.

Key Flags
zCompress / decompress
cCreate archive
xExtract archive
vVerbose output
fSpecify filename
Usage
  • tar -zcvf backup.tar folder1 folder2
    compress
  • tar -zxvf backup.tar
    extract
Backup with Date & Time
Append a Timestamp to Backup Filenames
  • tar -zcvf "backup$(date +%F_%T).tar" data
    result: backup2020-12-31_21:39:41.tar
  • tar -zcvf "backup$(date +%y%m%d%H%M%S).tar" data
    result: backup201231213941.tar
Date Format Codes
%FFull date (YYYY-MM-DD)
%TFull time (HH:MM:SS)
%y%m%dYear / Month / Day
%H%M%SHour / Minute / Second
Crontab — Scheduled Tasks
Manage the Cron Service
  • service crond status
  • service crond start
  • service crond stop
  • service crond restart
Syntax: Mi Ho Dm Mo Dw <Command>
Field Ranges
MiMinutes — 0–59
HoHours — 0–23
DmDay of month — 1–31
MoMonth — 1–12 or Jan–Dec
DwDay of week — 0–6 or Mon–Sun
Some commands (tar, shutdown, reboot) need their full path — use which <command> to find it.
Crontab Examples
  • 10 20 * * *
    at 8:10 PM daily
  • */5 * * * *
    every 5 minutes
  • * */12 * * *
    every 12 hours
  • 32 18 17,21,29 11 *
    at 6:32 PM on Nov 17, 21, 29
  • 0 18 * * mon-fri
    at 6 PM, Monday–Friday
  • 0 18-20 * * mon-fri
    at 6, 7 & 8 PM, Monday–Friday
Crontab + Shell Script
Recommended Script Locations
/usr/local/bin/normal users
/usr/local/sbin/root
Setup Steps
  • touch /usr/local/sbin/backup.sh
    create script
  • chmod +x backup.sh
    make executable
  • crontab -e
    edit schedule
  • crontab -l
    list schedules
Full Example: Automated Backup
/backup.sh
/usr/bin/tar -zcvf "/backup$(date).tar" data
Crontab entry
0 18 * * * /backup.sh
Every day at 6 PM, the system runs backup.sh, which uses tar to create a timestamped backup.
Quick Review
zip -r / unzip tar -zcvf / -zxvf tar flags: zcvf / zxvf date +%F_%T crontab -e / -l Mi Ho Dm Mo Dw */5 * * * *

CH 08
DNS Server
Name resolution with BIND: zones, record types, FQDN, and a full CentOS DNS server setup.
What Is DNS?

DNS (Domain Name System) converts a human-readable hostname (e.g. www.makara.com) into an IP address (e.g. 200.200.200.1).

Name Serverthe DNS server — stores and manages records
Resolverthe DNS client — queries the server, passes IP to the browser
Each DNS client must be manually registered by an administrator (static record).
Name Resolution Process
  • DNS client (resolver) needs an IP for a hostname
  • It sends a query to its DNS server
  • The DNS server looks up the record and responds with the IP
  • The resolver passes the IP to the web browser
Zones & Record Types
Zones

DNS databases are organized into zones — the zone name matches the domain name.

Forward LookupName → IP · stores A (Host) records
Reverse LookupIP → Name · stores PTR records
Record Types
A (Host)Hostname → IP — WSERVER1 IN A 192.168.1.1
PTRIP → Hostname — 1 IN PTR ns1.centos.kh.
CNAMEAlias — www IN CNAME WSERVER1
FQDN — Fully Qualified Domain Name

An FQDN combines a Host Name and a Domain Name, e.g. www.makara.com = host www + domain makara.com.

Roottop-level DNS server
Top Levelservers registered with Root (e.g. .com, .kh)
Second Levelservers registered under Top Level (e.g. makara.com)
BIND Configuration (CentOS)
Step 1 — Hostname & IP
  • vi /etc/sysconfig/network
    NETWORKING=yes, GATEWAY, HOSTNAME=centos.kh
  • vi /etc/hosts
    192.168.100.1 ns1.centos.kh ns1
DNS Server192.168.100.1 — centos.kh
CentOS Client192.168.100.2 — client1.centos
Windows Client192.168.100.3
Step 2 — Install & Configure BIND
  • dnf install bind bind-utils -y
  • vi /etc/named.conf
    edit options{} below
Inside options { }
listen-on port 53 { 127.0.0.1; 192.168.100.1; };
allow-query { localhost; 192.168.100.0/24; };
// comment out listen-on-v6
Step 3 — Zone Registration named.conf
Forward Lookup Zone
zone "centos.kh" IN {
  type master;
  file "/var/named/centos.kh.db";
  allow-update { none; };
};
Reverse Lookup Zone
zone "100.168.192.in-addr.arpa" IN {
  type master;
  file "/var/named/192.168.100.db";
  allow-update { none; };
};
Step 4 — Create Zone Files
/var/named/centos.kh.db (Forward)
@ IN SOA ns1.centos.kh. root.centos.kh. (
  1001 ;Serial   3H ;Refresh   15M ;Retry
  1W ;Expire   1D ;Minimum TTL )
@  IN NS  ns1.centos.kh.
ns1 IN A  192.168.100.1
/var/named/192.168.100.db (Reverse)
@ IN SOA ns1.centos.kh. root.centos.kh. (
  1001 ;Serial   3H ;Refresh   15M ;Retry
  1W ;Expire   1D ;Minimum TTL )
@  IN NS  ns1.centos.kh.
1   IN PTR ns1.centos.kh.
Step 5 — Restart & Firewall
  • systemctl restart named
  • systemctl enable named
  • firewall-cmd --permanent --add-port=53/udp
  • firewall-cmd --reload
Step 6 & 7 — Test
On the CentOS client, set DNS to 192.168.100.1 in /etc/resolv.conf
  • dig ns1.centos.kh
    verify forward lookup
  • dig -x 192.168.100.1
    verify reverse lookup
  • ping ns1.centos.kh
On Windows: set DNS server to 192.168.100.1, then ping the IP and hostname.
Create Records
  • vi /var/named/centos.kh.db
    add A record: www IN A 192.168.100.1
  • vi /var/named/centos.kh.db
    add CNAME: test IN CNAME www.centos.kh.
  • systemctl restart named
    apply changes
Test All Records
  • ping 192.168.100.1
  • ping ns1.centos.kh
  • ping www.centos.kh
  • ping test.centos.kh
Quick Review
Name Server vs Resolver Forward = Name→IP (A) Reverse = IP→Name (PTR) CNAME = alias dnf install bind bind-utils /etc/named.conf dig / dig -x
CH 09
Web Server
Install and configure Apache HTTP Server on CentOS, then secure it with SSL.
What Is a Web Server?

An Internet service used to host websites.

  • Stores website files and web pages
  • Displays information to users through a browser
  • Provides downloadable files or data to clients
  • Supports website administration & maintenance
How a Client Accesses a Website
  • Client enters a website address in a browser
  • DNS resolves the address of the web server
  • The client connects to the web server
  • The web server sends the requested page back to the browser
Setup Roadmap
6 Steps to a Running Web Server
1. Set up IP addresses 2. Install Apache 3. Allow firewall ports 4. Create a web page 5. Start & enable service 6. Test in browser
Network & Install
Network Setup
Server OSCentOS Server
Server IP192.168.1.5/24
Hostnamecentos.kh
Clientclient1.centos — same network
  • vi /etc/hostname
    set hostname
  • ping 192.168.1.5
    test connection
Install Apache & Disable SELinux
  • dnf install httpd -y
  • vi /etc/selinux/config
    set SELINUX=disabled
⚠ security disabling SELinux lowers security — in production, configure it properly instead.
Firewall & Test Page
Configure Firewall
  • firewall-cmd --permanent --add-port=80/tcp
    allow HTTP
  • firewall-cmd --permanent --add-port=443/tcp
    allow HTTPS
  • firewall-cmd --reload
Create Test Page & Start Service
Create /var/www/html/index.php with:
<h1>Hello World</h1>
  • systemctl start httpd
  • systemctl enable httpd
    auto-start on boot
Test Apache
On the client PC, open a browser and go to:
http://192.168.1.5
Expected: the test page loads — Apache is running correctly.
Secure Apache with SSL
Install & Generate Certificate
  • dnf install mod_ssl openssl
  • openssl genrsa -out ca.key 2048
    private key
  • openssl req -new -key ca.key -out ca.crt
    certificate request
  • openssl x509 -req -days 365 -in ca.crt -signkey ca.key
    generate certificate
Copy Files & Configure SSL
  • cp ca.crt /etc/pki/tls/certs/
  • cp ca.key /etc/pki/tls/private/
  • vi /etc/httpd/conf.d/ssl.conf
    inside <VirtualHost _default_:443>
Update these lines
DocumentRoot "/var/www/html"
ServerName 192.168.1.5:443
SSLCertificateFile /etc/pki/tls/certs/ca.crt
SSLCertificateKeyFile /etc/pki/tls/private/ca.key
Restart & Test HTTPS
  • systemctl restart httpd
On the client PC, open a browser and go to:
https://192.168.1.5
The site loads over HTTPS. The browser may warn about the certificate since it's self-signed.
Quick Review
dnf install httpd -y firewall-cmd --add-port=80/tcp /var/www/html/ systemctl enable httpd dnf install mod_ssl openssl /etc/httpd/conf.d/ssl.conf https://server-ip
